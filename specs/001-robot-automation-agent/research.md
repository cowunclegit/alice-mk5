# Research: Unified Plan, Analyze & Execute for Robot Agent

## Core Architectural Decisions

### Decision 1: Plan & Execute with Step Tracking
**Decision**: Implement a stateful execution loop that tracks the plan's progress using four primary fields:
- `plan`: The full sequence of intended actions generated by the Planner.
- `currentStep`: The specific action currently undergoing analysis or execution.
- `completedSteps`: A historical log of actions that have finished, including their results and extracted data.
- `remainingSteps`: A dynamic queue of actions yet to be performed.
**Rationale**: This ensures that even during complex analysis or replanning, the agent never loses its place in the overall workflow.

### Decision 2: Dynamic Analysis Phase (Cheerio Discovery)
**Decision**: Integrate a dedicated **Analyzer** node that processes each step before execution if a concrete selector is missing.
**Process**: 
1.  **Fetcher**: A "Get HTML" utility retrieves the current page source.
2.  **Pruning**: Noisy tags (scripts, styles, large SVGs) are stripped to reduce token costs and noise.
3.  **Extraction (Cheerio)**: All interactive elements are identified and converted into structured `ElementCandidate` objects.
4.  **Selection (LLM)**: The LLM matches the `currentStep.intent` against the candidate list to resolve the final `selector`.

### Decision 3: Human-in-the-loop Clarification
**Decision**: Transition to a **Clarifier** node if the Analyzer's confidence is low or if multiple ambiguous candidates are found.
**Rationale**: Provides a safety gate where the user can physically verify the target element in the visible browser before the agent performs a potentially destructive action.

### Decision 4: Incremental Replanning Loop
**Decision**: If a step fails technically or semantically, the **Reviser** node updates the `remainingSteps` based on the failure context and the current page HTML.
**Rationale**: Allows for targeted recovery (e.g., closing a pop-up) without discarding the progress logged in `completedSteps`.

## Integrated Flow Logic (The Graph)

1.  **Planner**: User Prompt -> High-level `plan` and initial `remainingSteps`.
2.  **Step Initialization**: Pop first action from `remainingSteps` -> set as `currentStep`.
3.  **Analysis Node**: 
    -   If `currentStep` needs a selector: Fetch HTML -> Cheerio Extract -> LLM Resolve -> Update `currentStep.selector`.
    -   If Confidence < Threshold -> **Clarifier Node** (User selection).
4.  **Executor Node**: Run Robot Framework keyword with the resolved selector.
5.  **Validator Node**: 
    -   Compare execution output against `intent`.
    -   On Success -> Move `currentStep` to `completedSteps` -> Loop to **Step 2**.
    -   On Failure -> Transition to **Reviser Node**.
6.  **Reviser Node**: 
    -   If retry limit ok -> Analyze failure + HTML -> Update `remainingSteps` -> Loop to **Step 2**.
    -   If retry limit reached -> **Manual Intervention**.
