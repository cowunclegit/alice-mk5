# Research: Simplified Reactive Agent Flow

## Decision: AXTree Format via Cheerio
- **Decision**: The Accessibility Tree (AXTree) generated by `cheerio` will follow a hierarchical JSON structure where each node contains `role`, `name`, `refId`, and `selector`.
- **Rationale**: This format mirrors standard accessibility trees used by tools like Playwright or Puppeteer while remaining lightweight for LLM consumption. `refId` allows the agent to refer to elements concisely.
- **Alternatives considered**: Full HTML (too token-intensive), raw text (loses structural meaning).

## Decision: DOM to AXTree Logic
- **Decision**: Implement a recursive "walker" using `cheerio` that maps HTML tags and ARIA roles to a unified set of simplified roles (e.g., `a` -> `link`, `button` -> `button`, `input[type="text"]` -> `textbox`).
- **Rationale**: Simplifies the variety of web tags into a few semantic categories that the LLM can easily reason about.
- **Alternatives considered**: Using `playwright`'s internal AXTree (rejected to minimize dependencies).

## Decision: Reactive Re-planning Trigger
- **Decision**: Trigger a re-plan cycle if the `validator` node detects a state that doesn't match the expected outcome or if the `analyzer` cannot find a suitable element in the AXTree.
- **Rationale**: Ensures the agent can pivot when the UI changes unexpectedly.
- **Alternatives considered**: Fixed retry counts (too brittle).
