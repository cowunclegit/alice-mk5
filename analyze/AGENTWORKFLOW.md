# OpenClaw Agent Browsing Workflow & Prompting Strategy

OpenClaw 에이전트는 단순한 명령 실행기가 아니라, 정교한 **시스템 가이드라인**과 **참조 기반 조작 전략**을 바탕으로 웹을 탐색하는 지능형 에이전트입니다. 이 문서는 에이전트가 브라우저 도구를 사용하는 워크플로우와 내부 프롬프트 전략을 상세히 분석합니다.

---

## 1. 에이전트 시스템 지침 (System Instructions)

에이전트에게 전달되는 `browser` 도구의 설명(Description)에는 AI의 행동 방식을 결정짓는 핵심 전략 3가지가 포함되어 있습니다.

### 전략 1: "Look Before You Leap" (관찰 후 행동)
*   **지침**: 페이지에 접근한 후, 어떤 조작을 하기 전에 반드시 `snapshot` 액션을 먼저 수행하라.
*   **이유**: 웹페이지의 UI는 동적으로 변하며, 에이전트가 요소의 정확한 위치와 상태를 파악해야만 오작동(Hallucination)을 방지할 수 있기 때문입니다.

### 전략 2: "Use Refs for Stability" (참조 번호 활용)
*   **지침**: 요소를 클릭하거나 텍스트를 입력할 때, 복잡한 CSS Selector나 모호한 텍스트 매칭 대신 스냅샷에서 부여된 고유 번호(예: `e12`)를 사용하라.
*   **이유**: `ref` 시스템은 브라우저 엔진이 계산한 절대적인 식별자이므로, 텍스트가 중복되거나 레이아웃이 미세하게 바뀌어도 조작의 정확성을 보장합니다.

### 전략 3: "Context Maintenance" (문맥 유지)
*   **지침**: `targetId`를 사용하여 현재 작업 중인 탭을 명시적으로 관리하라.
*   **이유**: 여러 탭을 오가며 작업을 수행할 때, 엉뚱한 페이지에 명령을 내리는 실수를 방지하고 세션의 연속성을 유지하기 위함입니다.

## 2. 상세 워크플로우 (Step-by-Step Scenario)

사용자가 **"구글에서 OpenClaw를 검색하고 공식 사이트 들어가줘"**라고 요청했을 때의 내부 워크플로우입니다.

### Step 1: 목적지 이동 (Navigate)
*   **에이전트 명령**: `browser(action: "navigate", targetUrl: "https://google.com")`
*   **서버 응답**: 이동 완료 메시지와 함께 새로운 `targetId` 반환.

### Step 2: 상황 인지 (Snapshot)
*   **에이전트 명령**: `browser(action: "snapshot", targetId: "tab-123")`
*   **서버 응답 (Role Snapshot)**:
    ```markdown
    - [1] textbox "검색" [ref=e1]
    - [2] button "Google 검색" [ref=e2]
    ```

### Step 3: 복합 조작 실행 (Action Batching)
*   **에이전트 명령**: `browser(action: "act", targetId: "tab-123", request: { ... })`
    *   에이전트는 `ref=e1`에 "OpenClaw"를 입력(type)하고, `ref=e2`를 클릭(click)하는 명령을 한 번의 배치로 보낼 수 있습니다.

### Step 4: 결과 확인 및 다음 단계
*   **에이전트**: 다시 `snapshot`을 찍어 검색 결과 페이지가 떴는지 확인하고, 공식 사이트 링크의 `ref` 번호를 찾아 다음 클릭을 준비합니다.

## 3. 에이전트 프롬프트 스키마 구조 (`BrowserActSchema`)

에이전트는 `act` 액션을 수행할 때 다음과 같은 정밀한 파라미터를 사용하여 사람과 유사한 동작을 시뮬레이션합니다.

| 파라미터 | 용도 | AI의 판단 근거 |
| :--- | :--- | :--- |
| **`kind`** | 동작 종류 (click, fill, type 등) | 요소의 Role(button이면 click, input이면 fill) |
| **`ref`** | 조작할 요소의 고유 번호 | 이전 `snapshot` 결과에서 추출 |
| **`slowly`** | 천천히 타이핑할지 여부 | 봇 탐지 우회나 자연스러운 입력이 필요할 때 |
| **`modifiers`** | Ctrl, Shift 등 조합 키 | 새 탭에서 열기(`Meta`+Click) 등이 필요할 때 |
| **`wait`** | 대기 조건 | 페이지 로딩이나 요소가 사라질 때까지 기다림 |

---

## 4. 장애 대응 전략 (Error Handling)

에이전트는 작업 실패 시 스스로 복구를 시도하도록 설계되었습니다.

1.  **Ref 유효성 상실**: 페이지가 리프레시되어 기존 `ref`가 무효화되면, 에이전트는 즉시 다시 `snapshot`을 찍어 번호를 갱신합니다.
2.  **요소 가려짐**: 클릭하려던 요소가 팝업 등에 가려졌다면, `screenshot`을 찍어 시각적으로 방해 요소를 확인한 후 팝업의 닫기 버튼을 먼저 찾아 클릭합니다.
3.  **타임아웃**: 페이지 응답이 느리면 `wait` 파라미터를 조정하거나 네트워크 상태를 체크하는 `status` 액션을 수행합니다.

---

## 5. 요약: OpenClaw 에이전트의 강점

OpenClaw 워크플로우는 **"추상화된 환경에서의 정밀한 조작"**을 가능하게 합니다.
*   **비결합성**: 에이전트는 복잡한 DOM 구조를 몰라도 되며, 오직 `ref` 번호와 `snapshot` 텍스트에만 집중합니다.
*   **안정성**: 사람의 브라우징 패턴을 모방하여(이동 → 관찰 → 조작) 자동화의 성공률을 극대화합니다.
*   **효율성**: 여러 동작을 하나로 묶는 `act` 배치를 통해 네트워크 왕복(Round-trip) 시간을 줄입니다.
